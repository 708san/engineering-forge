# 導入・更新の任意補助ツール（v0.10-dev）
AIが自由に考案した候補ファイルを、信頼できるローカルGitプロジェクトに新規ブランチとして構築する。製品分類・ファイル名・エージェント数を強制しない。Python 3.11以上、Git、Gitのコミット作成者設定が必要。ネットワーク・追加API不要。
## 利用
新規プロジェクトは対象ディレクトリでGitを初期化し、許可を得て初回コミットを作成する（空コミットでも可）。既存プロジェクトはHEADと作業ツリーを確認し、人間の変更を勝手にコミット・stash・削除しない。候補は対象外の別ディレクトリで作成する。
    python3 forge_integrate.py plan CANDIDATE TARGET
更新時は両コマンドに --prior PRIOR.json を追加する。PRIOR.json は以前に実際に採用された生成物の相対パスとSHA-256の対応表。人間のファイルを勝手に生成物扱いしない。取得できなければ既存ファイルの変更は競合として扱う。
計画の base、entries、token、omitted_prior を確認し、候補の内容・権限・保護要求・検証条件をレビューする。競合があれば人間の編集を保持して統合候補を作り直す。
    python3 forge_integrate.py stage CANDIDATE TARGET --expect REVIEWED_TOKEN --branch forge/initial --confirm
実際の書き込み権限と操作許可の確認が別途必要。--confirm はコマンドの実行意思であり人間承認の認証ではない。plan の終了コード0は競合なし、2は競合あり、1は検査不能。stage は成功0、停止1。独立した一時Git index から新規ローカルブランチを構築する。既存ブランチを更新せず、checkout・merge・pushもしない。Gitオブジェクトの書込は発生する。既存ブランチがあれば拒否する。
## 更新・採用・復旧
同一内容は変更しない。以前の生成物と現行版が一致するときだけ更新候補とする。人間だけが変えた内容は保持し、双方変更は停止する。削除済みの管理ファイルを復元しない。候補にない旧ファイルも削除しない。ignoredファイルや名前・ファイル/ディレクトリの衝突も確認する。
ブランチ作成後に git diff BASE forge/initial を確認する。権限の範囲で別worktreeまたはブランチの検証を行い、採用・統合は対象の正式運用に従う。ブランチ作成だけでは適用・検証済みではない。採用後、実際の採用内容を照合して next_prior_candidate を信頼済みの管理領域に保存する。未採用候補を次の基準にしない。以前の生成記録を維持する。
採用前の取り消しは候補ブランチを放置するか、利用者が必要な変更を保全してから削除する。採用後は対象の変更管理に従い、元コミットの逆変更を新しい候補として評価する。自動削除・履歴改変・自動revertは実装していない。
## 制約
信頼できる静止したローカル作業領域を想定。同時変更は再検査するが、敵対的ファイルシステムや最後の検査とref作成の間の競合を完全には防げない。統合時に改めてHEAD・作業ツリー・差分を確認する。Git設定・フック・外部コマンドは信頼済み環境が前提。未コミット/未追跡ファイルがある場合は停止する。Gitの変換フィルターや改行変換でcheckout内容がblobと異なる場合も保守的に停止する。候補の新規ファイルは通常ファイルとして登録し、既存の実行ビットは維持。大容量データ、特殊パス、ファイルモードの変更、削除、サブモジュール、任意コード実行、GitHubへの自動送信は対象外。失敗時は未参照Gitオブジェクトが残り得る。権限・正当性・意味・保護要求・テストの検証は別。
