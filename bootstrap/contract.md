# 初期化・引き継ぎ契約
入力: 基盤参照先・取得版、自由記述の発意または既存資産、許可された操作・アクセス、利用環境、正式要求。不明事項は明示する。
参照元同定→共同要件定義・固有課題分析→方法・組織・品質・環境設計→候補生成→評価→許可範囲で適用→読込・最初の作業の確認。順序は探索に応じて往復可。文書で権限を拡大しない。
候補は既存資産と分離し、入口、発意・要求への参照、設計、進捗・受入・変更・自律性の方針、出所の版、未確認事項、初回タスクを保持。必要な場合だけ固有の Skills、サブエージェント設定、テスト、ワークフロー等を生成する。固定数やカテゴリは要求しない。
適用計画の将来契約: 対象ルート、相対パス、操作、旧内容ハッシュまたは不存在条件、新内容ハッシュ、理由、依存、機密性、許可条件、復元手順。ルート外・リンク・競合を拒否し操作直前に再確認する。途中失敗の回復を設計する。
preview は候補/対象の読み取り専用比較のみ。v0.10-dev では新規ローカルGit統合ブランチへの追加・三者比較更新を部分実装した（integration.md）。既存作業ツリーの自動適用・削除・復元・権限強制・外部送信は未実装。
状態 referenced / designed / generated / applied / runtime_verified / blocked を対象ごとに区別し、状態は権限を付与しない。生成先に知識を閉じ、基盤更新の自動適用を禁止する。
正式受入 B01 URLから版を確認して開始、B02 未知案件に固有設計、B03 候補生成で対象を変更しない、B04 権限不足の明示、B05 対象の独立性、B06 同時変更検出、B07 再開、B08 実機読込と初回作業。いずれも正式受入未完了。
