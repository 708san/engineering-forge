# ChatGPT・Codex 実運用の4つの開始例
対象: v0.18.0-preview.5。以下は利用者の入力状況によって開始点を選ぶ例であり、製品分類・固定ルート・必須手順ではない。複数を組み合わせてよい。すべての補助機能は任意。
## 共通の準備
ChatGPT: 対象ごとに会話またはプロジェクトを用意。既存GitHubを使う場合は対象へのアクセスを確認。URLを渡し、AIが実際に取得した版を確認する。通常のGitHub連携は読み取り中心。利用環境が書込・実行に対応しないなら候補ファイルとCodexへの引き継ぎを作る。
Codex: アプリ・エディタ拡張・端末等で対象フォルダを開く。新規なら空の専用フォルダ。Forge本体と対象を分離し、URLから取得不能ならタグ固定のソースを別フォルダに用意して読取を許可する。既存のAGENTS.md（AI向けの開発指示書）・Skills・Gitの編集を保持する。インストールは不要。操作権限を無条件に拡大しない。
共通の参照先: https://github.com/708san/engineering-forge/tree/v0.18.0-preview.5 の START.md。初回だけでよい。

## 1. 既存プロジェクトに導入する
入力: 対象リポジトリ/パス、維持したい目的・制約（任意）。
目標: 現在の開発体制と実装の課題を観測し、必要な改善だけ採用する。既存の有効な手法を維持する。
### ChatGPTへの指示
> https://github.com/708san/engineering-forge/tree/v0.18.0-preview.5 の START.md を参照してください。対象: [GitHub URL]。既存の目的・要求・コード・テスト・開発方針・進捗を確認し、開発体制の不足や過剰さを根拠付きで分析してください。既存資産を保持した改善案と導入差分を考案し、委任内で実装・検証してください。書込や実行ができない場合はCodexがそのまま実施できる引き継ぎを作ってください。
### Codexへの指示
> https://github.com/708san/engineering-forge/tree/v0.18.0-preview.5 の START.md を参照し、現在開いているプロジェクトに必要な範囲だけ導入してください。先に実際のGitの現在版・未コミット変更・AGENTS.md・既存のテスト・仕様を調べてください。既存資産を保持する改善候補と差分を別ブランチまたは別作業領域で作り、委任内の改善と実装を行い、回帰試験を実行してください。保護条件の変更や予期しない競合は保留してください。
期待成果: 既存状況の把握、改善の根拠、必要最小の差分、観測した試験結果、次の作業。導入のためだけに全面再構築しない。

## 2. 新しいプロジェクトをゼロから共同設計する
入力: 興味、課題意識、目指したい価値など。具体的な製品・機能を決めている必要はない。
目標: 人間と共同で構想そのものを具体化する。価値、対象、体験、成立性を検討し、重要判断と暫定仮説を分離。開発体制は目的に応じて考案する。
### ChatGPTへの指示
> https://github.com/708san/engineering-forge/tree/v0.18.0-preview.5 の START.md を参照してください。まだ製品の形を決めていません。[興味・課題・構想]。私と共同で本質的な価値、対象利用者、問題、代替案を検討し、プロダクトの方向性と必要成果を具体化してください。必要な調査や可逆的な試作を進め、重要な価値判断は私と協議してください。方向性と実装範囲が決まったら、その製品に適した開発体制を設計し、合意・委任した範囲で開発を開始してください。
### Codexへの指示
> https://github.com/708san/engineering-forge/tree/v0.18.0-preview.5 の START.md を参照してください。現在のフォルダは新規開発用です。[興味・課題・構想] をもとに、私とプロダクトを共同設計してください。未決定の価値判断と検証できる仮説を区別し、必要な小規模試作や技術検証を行ってください。合意した目的・実装範囲に基づき必要最小の開発体制とコード・テストを作ってください。許可のない外部公開や新規リモート作成はしないでください。
期待成果: 選択肢と判断理由、明示された発意、暫定仮説と保留、検証可能な目的、必要最小の試作・開発体制。構想を早まって固定しない。

## 3. やりたいことを実現するために実装する
入力: 実現したい機能、体験、作業の自動化、利用場面。実装方法は未確定でもよい。
目標: 成果を中心に設計を絞り、実際に使える機能を早く作る。ゼロから事業企画をやり直さない。必要な仕様・例外・制約・テストをAIが具体化する。
### ChatGPTへの指示
> https://github.com/708san/engineering-forge/tree/v0.18.0-preview.5 の START.md を参照してください。やりたいこと: [実現したいこと]。入力、期待する出力、利用条件、不明な重要条件を整理し、目的を達成できる最小の実装方法を考案してください。可逆で委任内の判断は任せます。調査・実装・テストまで進め、実行できない部分はそのままCodexに渡せる成果物と手順にしてください。
### Codexへの指示
> https://github.com/708san/engineering-forge/tree/v0.18.0-preview.5 の START.md を参照し、[実現したいこと] を現在のフォルダで実装してください。入力・出力・例外・制約・完了条件を必要な範囲で具体化し、最小の技術構成を選択してください。コードを書き、実際にテストし、不具合を修正して利用手順まで整備してください。既存仕様と重要判断は保持し、許可範囲内で進めてください。
期待成果: 動作する機能、利用手順、期待出力と例外の検証、必要な開発指示。大規模な組織・文書管理は必要性がある場合だけ作る。

## 4. 要件定義がある程度決まっている
入力: 要件文書、設計資料、受入条件、確定した範囲と未確定部分（ファイル・URL・対象リポジトリ等）。
目標: 確定要求を基準に設計・実装する。明示要求・不足・矛盾・派生案を区別。欠落は補うが既存要求を無断変更しない。
### ChatGPTへの指示
> https://github.com/708san/engineering-forge/tree/v0.18.0-preview.5 の START.md を参照してください。要件・資料: [ファイル/URL]。明示・確定済みの要求を維持し、矛盾、抜け、検証不能な条件を分析してください。重要な変更だけ私に確認し、委任内で技術構成・開発体制・受入試験を具体化し、実装・検証に進んでください。実行できない作業はCodex用の契約・差分・検証方法として残してください。
### Codexへの指示
> https://github.com/708san/engineering-forge/tree/v0.18.0-preview.5 の START.md を参照してください。[要件の場所] の確定要求を基準に、現在のフォルダで開発してください。要求と実装・テストを対応付け、重要な不明や矛盾は保留し、関係のない作業を進めてください。実装・回帰試験・受入条件の検証を実行し、未達・未実施を明記してください。都合よく要件や品質基準を変更しないでください。
期待成果: 確定要求の正本、設計と実装、検証対応、未達と保留、次の作業。要件が不足しているだけで全体を再定義しない。

## 導入後・切替
対象の入口を使って「現在の正本と実装状態を確認して、開発を続けて」「この機能を追加して」「品質監査をして」で運用する。ChatGPTとCodexの切替時は対象URL/パスと実際の版、依頼を渡す。未コミット編集が別端末から見えるとは仮定しない。権限・テスト・読込の実測を報告。操作可能なら実装まで、できなければ候補と引き継ぎを作る。基盤のURLを毎回渡さない。
不具合や過剰工程は基盤担当の会話に自然言語でフィードバック。私的情報を公開Issueに書かない。OPERATE.md と feedback.md を参照。
