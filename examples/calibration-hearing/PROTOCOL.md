# Protocol model and verification
## State and conflict model
A testimony has sequential immutable text revisions. A narrator decision changes a monotonically increasing publication epoch. A correction always withdraws the current projection. A withdrawal increments the epoch even when already private; delayed publication commands with an older epoch fail. Publication explicitly selects the current revision and zero or more immutable, matching-revision interpretations.
An offline interpretation submission is a private append, with a stable draft ID, author label and referenced testimony revision. Exact retries do nothing; different content with the same ID is a conflict. Old revision drafts are preserved for narrator review, not made public. This is not a full offline sync implementation: it models the receiving side only.
## Trust boundary
The model assumes a trusted caller has authenticated the actor before invoking a narrator-only operation. Strings are not credentials. The Python object is not a security boundary. A single sequential caller is assumed; concurrent calls, persistence, transactions, authentication, access logs and network protocols are not implemented. The projection omits private history and editor IDs, but the selected content itself can contain identifying text. No claim of anonymization. The system cannot revoke an already received external copy; the test deliberately retains such a copy.
## Quality strategy
Use transition sequences rather than only isolated function tests: publish → withdraw → stale replay → remain private; publish → correction → stale interpretation → reject; concurrent intentions represented as sequential competing commands with the same epoch. Check private history and projection separately, explicit re-publication, idempotent retry, permission labels, stale revisions. Tests exercise only synthetic data and declared behavior.
## Alternative considered
A multi-writer replicated event log would help offline editing but increases complexity of withdrawal, authority and conflict resolution. A single authoritative publication state is the smaller experimental implementation; offline draft creation can be separated from publication. A real product may need a different model after requirements and risks are clarified. Avoid deciding privacy policy through the choice of synchronization algorithm.
