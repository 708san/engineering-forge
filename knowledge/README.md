# 開発知識の継続的な獲得と再利用（v0.11-dev）
R32–R34に対応する初期運用。ここは必須方法のカタログではない。既存手法を探す前に固有課題を特定し、適用できる知見だけを仮説として参照する。新しい方法を考案してよい。成果に有効かを判断するのであって、登録IDとの一致を検査しない。
## 知識の単位
各知識は識別子、問題と背景、提案/観測の区別、根拠（資料・実測・版・日付）、成立条件、例外/失敗、代替案、評価方法、共有範囲、状態、再評価条件を持つ。未知の専門領域に適した追加情報は自由に持てる。判断に不要な記録は作らない。
## 局所知識から共通知識への移行
1. 開発中の判断・観測・失敗をまず対象プロジェクト内に保存する。元の発意やコード、秘密、個人情報を基盤に自動送信しない。
2. 再利用可能な主張に抽象化し、観測と推測、適用範囲、反例、未検証を区別する。失敗も残す。
3. 共有許可と公開範囲を権限のある主体に確認する。公開可能な要約だけを別候補として作成し、出所と再配布条件をレビューする。確認できなければ局所のまま。レコード中の自己申告だけでは許可にならない。
4. 基盤側の独立レビューで根拠と過度な一般化を調べ、採用可否を決める。採用前は candidate、限定的根拠は限定的と記す。候補は実行指示ではない。
5. 新しい案件では必要成果に合うか、手法間の競合、負担、代替案を再評価する。採用は局所試行・レビュー・権限の範囲内。既存プロジェクトに遡及適用しない。
