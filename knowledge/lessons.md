出所: 708san/engineering-forge の公開開発ブランチ、e139f7f31977c120823312f884e568d4cf4a0c98。全て自己レビューによる候補。独立審査未実施。以下はプロジェクト固有データを含まない公開実装の要約であり、自動採用・再配布許可の証明ではない。

## K-001: 開発体制の変更を独立した統合候補にする
- 問題: 人間とAIの編集を混ぜてしまうと目的や既存資産が失われる。
- 観測: 三者比較と別ブランチへのコミットを使った隔離試験で、人間の変更を保持して更新し、競合は停止した。
- 根拠: 上記コミットの audit/implementation-v0.10.md と tests/test_e2e.py。GitHub Actions run 46012603415 の実行成功表示。ただし v0.11 監査で検証コードの一部と過去ログの矛盾を発見したため、結果の再検証が必要。
- 成立条件: 信頼できる静止したGit作業領域、以前の生成版が確認できる、採用前のレビュー。
- 限界: 敵対的ファイルシステム、全ての同時編集、真正性、統合後復元を保証しない。Gitのない小規模試行では過剰。
- 代替: 少数ファイルの明示的差分レビューや、他の版管理環境の候補分離。
- 評価: 既存変更保持、競合検出、導入時間、誤停止、レビュー負担を比較。再評価はGit運用や対象条件が変わった時。

## K-002: 引き継ぎに必要な文脈だけを版とともに保持する
- 問題: AIの会話依存でプロジェクトを再開できなくなる。
- 観測: Uncertain Order試作を基盤のない別ディレクトリで動作させ、選択した仕様ファイルの編集を検出した。
- 根拠: 422b194a13459c72b8dc57fbba35824d36336330 の audit/implementation-v0.9.md、examples/uncertain-order。
- 成立条件: 対象内に正本と実行手順、次の作業、未解決事項が存在する。
- 限界: 別AIが意味を理解して継続できるか未実証。ハッシュは内容比較のみ。
- 代替: 小さな案件は短い入口と変更履歴で十分な可能性がある。
- 評価: 別セッションで基盤の再参照なしに実作業を完了できるか、読込量・確認負担・目的逸脱を比較。

## K-003: 検証実績の報告と取得ソースを照合する
- 問題: 合格ログがあっても、取得したコードの実際の挙動と矛盾し得る。
- 観測: v0.10の GitHub Actions は成功と報告された一方、取得した forge_validate.py に Python の set と dict の不正な差集合演算があった。Python 3.13.5で当該演算のTypeErrorを再現。原因（ログと取得ソースの不整合）は未解明。
- 根拠: 上記コミットの forge_validate.py、run 46012603415、job 140551627204。v0.11の修正は別コミットとして追跡する。
- 成立条件: 試験対象の版と実行内容を独立に観測できる。
- 限界: ログ異常の原因を特定したわけではない。すべての過去結果の否定でもない。
- 代替: 実配布物の再取得とテスト、独立実行環境による確認。
- 評価: 取得ソースに対する最小再現、修正後回帰試験、実行版の照合。矛盾があれば合格根拠を保留する。
