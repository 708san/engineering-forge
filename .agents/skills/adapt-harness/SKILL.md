# 継続的な適応
入力は現行基準、変更・観測・障害・工数・人間の訂正。現在の正式仕様と提案を分離する。
- 変更の起点、影響する成果・役割・タスク・証跡を特定。古い検証を有効と仮定しない。人間の発意の変更は明示的に記録する。
- 方法の問題か、能力・権限・環境の問題か、プロダクトの問題かを分ける。既存方法の改善・削減も候補に含める。
- 仮説、変更前の基準、比較方法、停止条件、復元手段を定義して許可範囲で試行する。品質条件や権限の自己緩和は禁止。
- 変更候補を別領域で作り、旧生成版・現行版・新候補を比較。競合を無断上書きしない。正式適用は別手順。
- 局所知識と共通知識を区別。成功だけでなく失敗・負担・適用条件を記録し、再利用許可と審査がなければ共有しない。
出力: 差分提案、影響分析、試行計画、証跡の再検証、判断待ち、次の安全な作業、引継ぎ。未実施を明示する。

共通知識の候補作成・共有・再利用は `../../../knowledge/README.md` を参照。局所の機密情報を転送せず、公開範囲の確認と独立審査を別工程にする。候補を採用済みとしない。

比較試行の具体的手順は `../../../bootstrap/adaptation.md`。必要な場合だけ任意の数値比較補助を利用する。候補の試行結果を自動採用しない。

## 判断の具体化（preview.3）
同じ失敗が繰り返されるなら、追加の作業指示だけでなく、知識・観測・分担・技術構成・人間との判断境界のどこに原因があるかを見直す。実測で改善を示せない場合は、複雑さを増やす提案を維持する必然性を再検討する。知識の再利用は元の適用条件と異なる場合の反例も調べる。詳細は `../../../knowledge/design-reasoning.md`。
