# 開発組織とエージェント設計
入力は成果、方法、タスク依存、リスク、利用可能な能力。役割とAIの数を混同しない。
- 誰が成果を所有し、設計・実装・検証・統合・判断の責任を負うか決める。新しい専門能力が必要なら調査してSkill候補を作る。
- 最小の単一構成を比較基準にする。分業する場合は独立性、専門性、並列性、文脈分離の利益と調整費用を説明する。協調構造は自由に設計できる。
- 作業契約に目的、基準版、範囲、禁止事項、入力、出力、受入条件、判断委任、操作権限、予算、停止条件、統合責任を記載する。
- 人間の直接編集を保護し、並行作業の対象ファイルと競合処理を決める。独立評価が必要な場合は別コンテキスト・実行権限・成果の変更禁止を個別に確認。利用不能なら保留または低い独立性を明記する。
- 常時読込の指示を短くし、担当固有の知識は必要時取得する。生成するSkillsは名前・説明・手順・参照を持つ。設定の存在だけで動作・権限強制を主張しない。
出力: roles、collaborations、役割と実行主体の割当、作業契約、環境別設定候補、実行不能事項。
