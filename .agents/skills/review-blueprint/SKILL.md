# 開発体制レビュー
入力は原文、正式要求と基準版、候補、環境能力、証跡。../../../evaluation-v0.5.md を参照。評価者は候補の実装や基準を変更しない。
1. 先に原文と正式要求から期待成果を確認し、候補が自ら定義した基準を無条件に受け入れない。目的置換、要求欠落、保護条件の弱体化を調べる。
2. 独自課題の発見、方法の合理性、代替案、成果との対応、役割の必要性、GitHub・環境の実行可能性、確認負担を評価する。同等の別解を認める。
3. 構文・参照の機械検査と意味レビュー、実環境試験を分離する。未検証・失敗・実行不能を合格にしない。承認は信頼済みの証跡に基づく。
4. 各指摘に重大度、根拠、影響範囲、期待する修正または検証を記録する。重大な未達は採用・公開を保留。独立作業は続行できる。
5. 同一セッションでのレビューは自己レビューと表示する。別コンテキストでも権限分離や人間の独立性を自動的に保証しない。
出力: 合否ではなく候補の判定（修正要・試行可・採用候補・保留）、未検証事項、証跡、残存リスク、独立性水準。正式な承認ではない。
