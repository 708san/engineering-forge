# 生成型方法論設計
入力は発意・成果・課題・知識・制約。../../../generative-architecture.md を参照する。
- 成果ごとに何を知り、何を作り、どう観測すれば達成を判断できるかを考える。既存手法を調べるのは選択肢を広げるためであり、P番号との一致を要求しない。
- 重要な判断では最小構成、既存方法の適応、新規方法等の実質的代替案を比較する。目的、前提、依存、活動、成果物、検証、失敗時対応、負担、再評価条件を記述する。新規性を理由に採用しない。
- 独自の品質特性や情報形式が必要なら定義する。拡張形式は版付きスキーマの候補として設計し、権限や承認には使わない。未知の形式は未検証。
- 成果に対応しない手法は削除する。満たせない必須成果は隠さずholdにする。探索段階の試行合格を本番適合としない。
- 採用理由、試行と正式採用の区別、既存の保護された成果の維持を確認する。試行失敗時は仮説・方法を見直し、必須成果を変えない。
出力: methods、artifacts、outcomesとの関係、代替案、実験・評価設計、holds。
