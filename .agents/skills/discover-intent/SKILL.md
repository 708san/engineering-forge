# 発意と固有課題の発見
原文を許可された保存範囲内で保持し、解釈を分ける。過去の却下案を再採用するなら理由を示す。既存コードは事実であり、要求ではない。
- 利用者の行為、入力、出力、状態、外部との境界、時間・空間・物理的性質、失敗時の影響を実際の構想から考える。列挙は例であり、未知の観点を追加する。
- 事実、ユーザー要求、解釈、仮説、不明を分離する。反例（例外条件、意図に反する利用、正常でも価値がない状況）を考え、原文との対応を示す。
- 達成すべき成果を「条件・期待する挙動・観測方法・必要な時期」にする。保護済みの要求を削除・緩和しない。未確定閾値は明示する。
- 調査で解決可能な不明は調査へ。重要で可逆な判断は委任内で暫定化。保護判断は確認待ちとし、独立作業を示す。
出力: 発意参照、discoveries、outcomes、未知の領域、知識不足、判断待ちと継続可能範囲。既存のカテゴリ名への一致を評価しない。
